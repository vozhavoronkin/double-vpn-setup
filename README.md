# VPN Chain Setup

Нативное macOS-приложение (SwiftUI) для полной автоматизации **двойной VPN-цепочки** по SSH:

```
Клиент AmneziaVPN → Сервер-вход (AmneziaVPN + Docker) → Сервер-выход → Интернет
```

Внешним миром клиент видит IP **сервера-выхода**, при этом сам подключается только к серверу-входу. Наружу (между двумя серверами) идёт лишь зашифрованный UDP-трафик relay-туннеля AmneziaWG.

Источник требований — ТЗ [`resources/vpn-chain-amneziawg-spec.md`](resources/vpn-chain-amneziawg-spec.md). Спецификации возможностей — в [`openspec/specs/`](openspec/specs/).

## Требования

- macOS 13+ (сборка — на macOS с Xcode 15+, Swift 6)
- Два сервера: Ubuntu 20.04+/Debian 11+ x86_64, root-доступ по SSH
  - **Сервер-вход**: Docker + установленный из приложения AmneziaVPN контейнер AmneziaWG (клиенты подключаются к нему)
  - **Сервер-выход**: чистая VM, порт **UDP 51828** открыт в firewall/панели провайдера
- SSH-аутентификация: пароль или ключ **ed25519/ECDSA** (RSA не поддерживается транспортом swift-nio-ssh)

## Сборка и запуск

```bash
xcodegen generate          # создать VPNChainSetup.xcodeproj из project.yml
open VPNChainSetup.xcodeproj
# scheme «VPNChainSetup» → Run

# или из терминала:
xcodebuild -project VPNChainSetup.xcodeproj -scheme VPNChainSetup \
  -destination 'platform=macOS' build

swift test                 # 146 unit-тестов core-модуля
```

## Установка из релиза

1. Скачайте `VPNChainSetup-<версия>-macos-universal.zip` со страницы [Releases](../../releases) и распакуйте.
2. Перенесите `VPNChainSetup.app` в «Программы».
3. **Сборка не подписана Apple.** При первом запуске macOS покажет предупреждение. Снимите карантин одним из способов:
   - терминал: `xattr -dr com.apple.quarantine /Applications/VPNChainSetup.app`
   - либо: правый клик по приложению → «Открыть» → «Открыть»; на macOS 15+ — «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть».
4. Проверьте целостность по `SHA256SUMS.txt` из релиза: `shasum -a 256 -c SHA256SUMS.txt`.

Требования: macOS 13+, серверы с доступом по SSH (подробнее — раздел «Требования»).

## Функциональность

### 1. Подключения
Профили обоих серверов: хост, пользователь, пароль или файл ключа, порт SSH (в блоке «Дополнительно»). Кнопка «Проверить соединение» выполняет контрольное подключение и показывает ОС/архитектуру сервера. Host key сервера закрепляется по принципу TOFU: при первом подключении отпечаток подтверждается вручную, при смене ключа — предупреждение и отказ.

Секреты (пароли, парольные фразы) хранятся **только в Keychain**; в файлах настроек — лишь хост/порт/логин/отпечаток.

### 2. Установка (полная автоматизация)
Один запуск разворачивает цепочку на паре серверов; порядок шагов зашит в конечный автомат:

1. **Детект окружения** на входе: контейнер AmneziaWG, Docker-сеть/подсеть/IP контейнера, интерфейс (`amn*` или из `ip route get`), клиентская подсеть и порт клиентского AWG из конфига внутри контейнера. Ничего не хардкодится — всё определяется динамически.
2. **Установка ПО** на обоих серверах: `amneziawg-go` и `amneziawg-tools` собираются из зафиксированных пинов (старая userspace-линия Go — совместима с ядрами со встроенным WireGuard). Шаги идемпотентны: повторный запуск пропускает готовое.
3. **Ключи и обфускация** relay-участка: ключи AmneziaWG генерируются на CryptoKit, параметры обфускации (Jc/Jmin/Jmax/S1/S2/H1–H4) — по правилам раздела 4 ТЗ, идентичны на обоих концах.
4. **Конфигурация** серверов: relay-туннель `10.99.0.0/24` (вход `10.99.0.1`, выход `10.99.0.2`), порт UDP 51828, юниты `awg-quick@awg-relay` + управляемые `vpn-chain(-exit).service`.
5. **Правила маршрутизации** на входе: отбор клиентского трафика по метке `fwmark` (не по интерфейсу — иначе ломался handshake клиентов), blackhole kill-switch (без туннеля трафик клиентов блокируется, реальный IP не утекает), цепочки в `DOCKER-USER`, анти-утечка IPv6. Host-трафик и SSH серверов не затрагиваются.
6. **Верификация**: handshake вход↔выход с повторами, живой вывод команд по шагам, итоговая сводка с подсказкой про UDP 51828 у провайдера.

### 3. Статус и проверки
Автоматические проверки раздела 10 ТЗ: возраст handshake, policy routing, туннель, порт 51828, NAT, контейнер не тронут — каждая с подсказкой при неуспехе. Ручные пункты чек-листа выводятся с инструкциями.

### 4. Диагностика
Помощь по симптомам раздела 11 ТЗ: «нет handshake», «handshake есть — интернета нет», «пересоздана Docker-сеть», «пропал SSH» (с rescue-командой для консоли провайдера) и др. Каждому симптому — набор проверок и советов.

### 5. Удаление (uninstall)
Откат только артефактов, установленных приложением (юниты, правила, конфиги, `/etc/amnezia/chain/`): **контейнер AmneziaVPN, SSH-доступ и установленное ПО не трогаются** — удаление только по явному подтверждению. После очистки входа клиент продолжает работать напрямую через сервер-вход.

### 6. Клиент
Пошаговая инструкция подключения AmneziaVPN (без split tunneling, KillSwitch, DNS через туннель, MTU 1380 при проблемах с UDP) и чек-лист проверок.

### 7. Прокси (опция, по умолчанию выключена)
Если на сервере-входе подняты дополнительные прокси (Xray/3x-ui, Shadowsocks, SOCKS5, MTProto), режим «Прокси» направляет их трафик — хостовых сервисов и Docker-контейнеров — через сервер-выход. Клиенты прокси видят IP выхода, а не входа.

- **Что маршрутизируется:** весь исходящий трафик сервера-входа и включённых Docker-сетей. Сеть AmneziaVPN исключена всегда, остальные сети можно исключить в списке.
- **Порядок применения:** сначала сервер-выход (маршруты и NAT подсетей), затем сервер-вход (маркировка). При ошибке на входе изменения откатываются, режим остаётся выключенным.
- **Проверка выхода:** кнопка сравнивает фактический публичный IP с сервера-входа и из каждого контейнера с IP сервера-выхода.
- **Ограничения:** приложение не устанавливает и не настраивает прокси-сервисы — аутентификация, пароли и firewall на прокси остаются на пользователе. Обновления пакетов, `docker pull` и DNS сервера-входа тоже пойдут через выход. Туннель IPv4-only, поэтому при включённом режиме исходящий IPv6 с входа и из контейнеров блокируется.
- **Выключение:** полное снятие цепочек, маршрутов и NAT на обоих серверах; контейнер AmneziaVPN и SSH не затрагиваются.

## Безопасность

- Секреты — в Keychain (`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`), не в UserDefaults и не в логах (журнал санитизируется: пароли/фразы/ключи маскируются).
- Отбор трафика на входе маркирует только пакеты контейнера (кроме ответов клиентам) — SSH и host-трафик не затрагиваются при любом состоянии туннеля.
- `AllowedIPs` пира на выходе не содержит `0.0.0.0/0` — выход не уводит собственный трафик в туннель.
- Все удалённые артефакты помечены `# managed-by: amnezia-chain` и перечислены в инвентаре удаления.

## Работа с репозиторием

- Ветка `main` защищена: изменения попадают только через pull request (требуется 1 аппрув; владельцу разрешён bypass при мерже).
- Force push и удаление `main` заблокированы для всех, включая администратора.
- Поток: ветка `feature/*` → коммиты → push → pull request → мерж → удаление ветки.

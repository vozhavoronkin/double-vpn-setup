# Proposal

## Why

Установка из релиза сейчас ручная и состоит из четырёх шагов: скачать zip,
проверить `SHA256SUMS.txt`, распаковать и перенести в `/Applications`, снять
карантин `xattr -dr com.apple.quarantine` (без этого шага приложение не
запускается — сборка не подписана Apple). Легко ошибиться или пропустить
проверку целостности (issue #4). Один скрипт в assets релиза сводит всё к
одной команде, где сверка контрольной суммы и снятие карантинного флага
выполняются автоматически и до установки.

## What Changes

- Новый скрипт `install.sh` в assets релиза (рядом с zip и `SHA256SUMS.txt`),
  который в автоматическом режиме:
  1. определяет версию: по умолчанию — последний релиз, опционально —
     версия, переданная первым аргументом (допущение, зафиксировано в design);
  2. скачивает zip текущей версии и `SHA256SUMS.txt` со страницы Releases
     «чистыми» средствами macOS (curl) — без Homebrew, Xcode и jq;
  3. сверяет SHA256; при несовпадении — отказ с ошибкой, **никаких изменений
     в системе не вносится**;
  4. распаковывает во временный каталог;
  5. снимает карантинный флаг `com.apple.quarantine`;
  6. копирует `VPNChainSetup.app` в `/Applications` (`sudo` при необходимости);
  7. печатает итог и напоминание, что сборка не подписана Apple.
- Требования к скрипту: `set -euo pipefail`, корректная работа с путями
  с пробелами, только системные утилиты macOS (работа на чистом Mac).
- Шаг упаковки скрипта в `.github/workflows/release.yml`: `install.sh`
  публикуется в assets релиза вместе с zip и `SHA256SUMS.txt`.
- README: установка одной командой как основной способ, ручная установка —
  как альтернатива.

## Capabilities

### New Capabilities
- `release-install`: установка приложения из релиза одной командой —
  публикация `install.sh` в assets релиза, контракт скрипта (выбор версии,
  загрузка, сверка SHA256 до любых изменений в системе, снятие карантинного
  флага, установка в `/Applications`, сообщения пользователю).

### Modified Capabilities
- Нет — существующие спеки описывают поведение самого приложения
  (провижининг, диагностика, SSH, UI), которое не меняется.

## Impact

- Новый файл `scripts/install.sh` (исходник в репозитории) — публикуется
  workflow'ом релиза.
- `.github/workflows/release.yml` — шаг упаковки/публикации скрипта,
  обновление текста тела релиза (установка одной командой).
- `README.md` — раздел «Установка из релиза» переписан: одна команда +
  ручной способ как альтернатива.
- Код приложения (`Sources/`, `Tests/`) не меняется; `swift test` остаётся
  зелёным. Поведение CI/релиза — единственная затронутая система.

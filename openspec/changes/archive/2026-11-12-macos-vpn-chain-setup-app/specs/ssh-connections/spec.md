# Spec Delta: ssh-connections

## Purpose

Даёт пользователю возможность настраивать и проверять SSH-подключения к двум серверам цепочки (С1 — вход, С2 — выход) и предоставляет всем остальным возможностям приложения единый безопасный транспорт выполнения удалённых команд.

## ADDED Requirements

### Requirement: Профили подключений
Приложение SHALL позволять создавать, редактировать и удалять профили SSH-подключения, каждый из которых содержит хост, порт, имя пользователя и способ аутентификации (пароль или приватный ключ). Приложение SHALL поддерживать ровно две роли серверов для цепочки: С1 (вход) и С2 (выход).

#### Scenario: Создание профиля
- **WHEN** пользователь вводит хост, порт, пользователя и выбирает способ аутентификации, затем сохраняет профиль
- **THEN** профиль сохраняется и отображается в списке подключений в соответствующей роли (С1 или С2)

#### Scenario: Редактирование профиля
- **WHEN** пользователь изменяет параметры существующего профиля и сохраняет
- **THEN** последующие операции с этим сервером используют новые параметры, а сохранённые секреты остаются доступными

### Requirement: Аутентификация по паролю и по ключу
Приложение SHALL поддерживать SSH-аутентификацию двумя способами: по паролю и по приватному ключу (выбор файла ключа, опциональная парольная фраза). При неудачной аутентификации приложение SHALL показывать понятную ошибку и предлагать повторить ввод.

#### Scenario: Подключение по паролю
- **WHEN** пользователь выбирает аутентификацию по паролю и вводит корректный пароль
- **THEN** соединение устанавливается без интерактивного терминала

#### Scenario: Подключение по ключу
- **WHEN** пользователь выбирает файл приватного ключа (с парольной фразой или без) и ключ принят сервером
- **THEN** соединение устанавливается; если задана парольная фраза, она запрашивается один раз и не запрашивается повторно в рамках сессии

#### Scenario: Неверные учётные данные
- **WHEN** сервер отклоняет аутентификацию (неверный пароль/ключ)
- **THEN** приложение показывает сообщение об ошибке аутентификации и возвращает пользователя к вводу учётных данных, не завершая работу с профилем

### Requirement: Хранение секретов в Keychain
Приложение SHALL хранить пароли SSH и парольные фразы ключей в macOS Keychain. Приложение MUST NOT записывать секреты в файлы настроек, экспорты или журналы в открытом виде.

#### Scenario: Сохранение пароля
- **WHEN** пользователь сохраняет профиль с паролем
- **THEN** пароль сохраняется в Keychain, а в файлах приложения хранится только признак «пароль задан»

#### Scenario: Секреты не попадают в журнал
- **WHEN** выполняется любая операция, записываемая в журнал приложения
- **THEN** пароли, парольные фразы и содержимое приватных ключей в журнале отсутствуют или замаскированы

### Requirement: Проверка соединения
Приложение SHALL позволять проверить профиль до начала операций: установить соединение, выполнить контрольную команду и показать результат (успех, версия/архитектура ОС сервера либо причина отказа с таймаутом).

#### Scenario: Успешная проверка
- **WHEN** пользователь запускает проверку доступного сервера
- **THEN** приложение показывает успех и сведения об ОС/архитектуре (например, «Ubuntu 22.04, x86_64»)

#### Scenario: Недоступный сервер
- **WHEN** сервер не отвечает или порт закрыт
- **THEN** по истечении таймаута приложение показывает причину (таймаут/DNS/отказ в соединении) и не начинает операции установки

### Requirement: Единый транспорт команд
Все удалённые операции приложения SHALL выполняться через один слой SSH-транспорта, который задаёт таймауты, фиксирует код возврата, поток stdout/stderr и записывает операции в журнал. Длительные команды SHALL транслировать вывод в интерфейс по мере поступления.

#### Scenario: Выполнение команды с таймаутом
- **WHEN** удалённая команда не завершается в пределах таймаута шага
- **THEN** транспорт разрывает выполнение, сообщает об ошибке с кодом/причиной, и операция шага помечается как незавершённая

#### Scenario: Длительная команда
- **WHEN** выполняется долго идущая команда (например, сборка пакета)
- **THEN** её вывод отображается пользователю по мере поступления, а не после завершения

# Proposal

## Why

`resources/vpn-chain-amneziawg-spec.md` описывает рабочую, но полностью ручную схему «двойного AmneziaWG»: агент/пользователь должен по SSH выполнять десятки команд на двух серверах (сборка `amneziawg-tools`/`amneziawg-go` с подбором версии Go, генерация ключей и параметров обфускации, policy routing, `DOCKER-USER`-правила, systemd-юниты, payload для С2). Процесс долгий, требует shell-экспертизы и легко ошибиться в порядке шагов. Нужен нативный macOS-инструмент, который выполняет всю схему по кнопке и делает её повторяемой, наблюдаемой и обратимой.

## What Changes

- Создаётся новое нативное macOS-приложение (Swift/SwiftUI, минимум macOS 13), которое автоматизирует развёртывание VPN-цепочки из ТЗ по SSH (пароль + ключи).
- Профили подключения: хост/порт/пользователь/аутентификация для С1 и С2, пароли — в Keychain, проверка доступности до начала работы.
- Полная автоматизация provisioning: детект Docker-окружения на С1 (контейнер, бридж, подсети), установка ПО на обоих серверах из одного commit, генерация секретов, конфиги `awg-relay` (шаблоны 9.1/9.2 ТЗ), systemd-юниты, правила policy routing/firewall, запуск и проверка handshake — без ручного копирования скриптов.
- Генерация секретов по правилам раздела 4 ТЗ (включая исправление найденных в ТЗ ошибок: rp_filter на интерфейсе `awg-relay`, отказ от захардкоженного имени контейнера — имя всегда берётся из результата детекта).
- Диагностика: статус туннеля/правил, проверочные команды раздела 10, подсказки troubleshooting раздела 11, корректный uninstall (контейнер AmneziaVPN и SSH-доступ не затрагиваются).
- Клиентская сторона (раздел 8 ТЗ) остаётся ручной: приложение показывает инструкцию и проверочные шаги, но не управляет AmneziaVPN на Mac.

## Capabilities

### New Capabilities

- `ssh-connections`: управление профилями SSH-подключений к С1/С2 (хост, порт, пользователь, пароль или ключ), хранение секретов в Keychain, проверка соединения; единый транспорт выполнения команд для всех остальных возможностей.
- `chain-provisioning`: автоматическое развёртывание relay-цепочки на паре серверов — детект окружения С1, установка amneziawg-tools/amneziawg-go (один commit, fallback на свежий Go), применение конфигов, правил и юнитов на С1 и С2, идемпотентность, гарантии безопасности (контейнер `amnezia-awg` и host-SSH не затрагиваются, kill-switch обязателен).
- `relay-secrets`: генерация и согласование ключей и параметров обфускации AmneziaWG для relay-участка по правилам ТЗ (`S1/S2/H1–H4` совпадают, `S2 ≠ S1 + 56`, `H1–H4` попарно различны, значения «обфускация выключена» запрещены), безопасное хранение (0700/0600, приватные ключи не попадают в логи).
- `chain-diagnostics`: просмотр состояния цепочки (handshake, счётчики, правила, юниты), выполнение проверок раздела 10 ТЗ, подсказки по разделу 11, uninstall без ущерба для AmneziaVPN и SSH-доступа.

## Impact

- Новый код: Xcode-проект (SwiftUI-приложение) в корне репозитория — сегодня кода нет, конфликтов нет.
- Новые зависимости: SSH-библиотека для Swift (swift-nio-ssh или обёртка libssh2), системные Keychain API; точный список фиксируется в design.md.
- Внешние системы: два Linux-сервера (Debian 11/12/13, Ubuntu 20.04/22.04/24.04, x86_64/aarch64) с Docker и контейнером amnezia-awg на С1; права root по SSH.
- Существующие файлы репозитория не изменяются; `resources/vpn-chain-amneziawg-spec.md` остаётся источником истины схемы (в артефактах зафиксированы три исправления к нему).

# Proposal

## Why

Помимо AmneziaVPN на сервере-входе часто поднимают дополнительные прокси (Xray/3x-ui, Shadowsocks, SOCKS5, MTProto). Сейчас в туннель к серверу-выходу уходит только трафик клиентов AmneziaWG (отбор по `fwmark`), поэтому клиенты дополнительных прокси видят IP входа, а не выхода. Нужна выключенная по умолчанию опция, направляющая весь исходящий трафик сервера-входа — хостовых сервисов и Docker-контейнеров — через сервер-выход (issue #8).

## What Changes

- Новый глобальный режим «Прокси» (по умолчанию выключен): весь исходящий трафик сервера-входа, кроме сети AmneziaVPN и исключённых Docker-сетей, маркируется и уходит через relay-туннель.
- На сервере-входе: новые цепочки маркировки `VPNCHAIN_HOST_OUT` (mangle OUTPUT, хостовые сервисы) и `VPNCHAIN_DOCKER_OUT` (mangle PREROUTING, контейнеры) поверх существующей маршрутизации `fwmark → таблица 51821`; существующие правила Amnezia не меняются.
- На сервере-выходе: маршруты и MASQUERADE для включённых Docker-подсетей входа; список применённого хранится для идемпотентной очистки.
- Порядок применения «выход → вход» с откатом при ошибке на входе.
- Применённое состояние — `/etc/amnezia/chain/proxies.json` (0600, маркер `managed-by: amnezia-chain`) на обоих серверах; настройка (вкл/выкл, исключённые сети) — в профиле приложения.
- Новый раздел «Прокси» в UI: переключатель, список Docker-сетей с чекбоксами, применение, проверка фактического IP выхода (хост + каждый контейнер).
- Блокировка IPv6-исходящего с входа и из контейнеров при включённом режиме (туннель IPv4-only, иначе утечка).
- Новые диагностические проверки (`proxy-host-egress`, `proxy-docker-networks`, `proxy-exit-nat`, `proxy-egress-ip`) и записи в таблицу симптомов.
- Полное снятие правил при выключении/удалении только по маркеру; контейнер AmneziaVPN и SSH не затрагиваются.
- Приложение НЕ устанавливает и не настраивает сами прокси-сервисы — только обеспечивает маршрут.

## Capabilities

### New Capabilities
- `proxy-egress`: опциональный глобальный режим направления всего исходящего трафика сервера-входа (хост + Docker-сети) через сервер-выход: правила маркировки на входе, маршруты/NAT на выходе, идемпотентное применение/откат/удаление по маркеру, хранение состояния, IPv6-kill-switch.

### Modified Capabilities
- `app-interface`: новый раздел «Прокси» в sidebar (`AppSections.all`): переключатель, список Docker-сетей, применение, проверка фактического выхода, предупреждение об ответственности пользователя.
- `chain-diagnostics`: новые проверки proxy-* и записи в таблицу симптомов; диагностика дрейфа Docker-сетей.

## Impact

- `Sources/VPNChainCore/Provisioning/ConfigureC1.swift`, `ConfigureC2.swift` — рендер новых цепочек/маршрутов.
- `Sources/VPNChainCore/Provisioning/EnvironmentDetection.swift` — детект Docker-сетей (имя, подсеть, bridge), IP выхода.
- `Sources/VPNChainCore/Provisioning/ProvisioningEngine.swift` — шаги применения в порядке «выход → вход», откат.
- `Sources/VPNChainCore/Secrets/ChainState.swift` / профили — настройка режима и исключённых сетей.
- `Sources/VPNChainCore/Diagnostics/ChecksEngine.swift`, таблица симптомов, `UninstallPlan` — очистка.
- `Sources/VPNChainSetup/Views/AppRootView.swift`, `ViewModels/`, `DesignSystem.swift` — раздел «Прокси».
- Unit-тесты рендера правил; приёмка на реальной паре; README/CHANGELOG; релиз 0.2.0.

# Design

## Context

Релизы собирает `.github/workflows/release.yml` (триггер — тег `v*`): universal-сборка,
`ditto -c -k` в `VPNChainSetup-<версия>-macos-universal.zip`, `shasum -a 256 > SHA256SUMS.txt`,
публикация `softprops/action-gh-release@v2`. Установка сейчас — четыре ручных шага
(см. proposal.md, issue #4). Целевая среда скрипта — чистый Mac: macOS 13+, предустановленные
`/bin/bash` (3.2), `curl`, `shasum`, `ditto`, `xattr`, `sudo`; нет Xcode, Homebrew и `jq`.
Скрипт не имеет зависимостей из репозитория: публикуется в assets как есть и работает сам.

## Goals / Non-Goals

**Goals:**
- `install.sh` в assets релиза: одна команда от «скачал» до «приложение в /Applications без карантина».
- Строгая проверка целостности **до** любых изменений в системе.
- Минимум зависимостей: только предустановленные средства macOS; bash-совместимость с 3.2.
- Предсказуемые отказы: любая ошибка — чистый выход без следов установки.

**Non-Goals:**
- Подпись/нотаризация сборки (остаётся «без подписи Apple»).
- Homebrew-формула, cask, Sparkle-обновления, auto-update.
- Проверка подписи/нотаризации codesign'ом — только SHA256 из релиза.
- Изменения кода приложения и его спеков.

## Decisions

1. **Источник «последнего релиза» — redirect, а не GitHub API.**
   `https://github.com/<owner>/<repo>/releases/latest` отвечает 302 на
   `.../tag/vX.Y.Z`; тег извлекается из `url_effective` (`curl -sIL -o /dev/null -w '%{url_effective}'`).
   Альтернатива — `api.github.com/repos/.../releases/latest` — лимитирована (60 req/час без
   токена) и требует парсинга JSON без `jq`. Redirect-трюк без лимитов и без парсинга JSON.

2. **Скрипт — `#!/bin/bash`, синтаксис bash 3.2.** На чистом Mac есть только bash 3.2
   (`/bin/bash`); без ассоциативных массивов и `${var,,}`. `set -euo pipefail` в первой
   строке тела; ловушка `trap cleanup EXIT` удаляет временный каталог.

3. **Имена assets выводятся из тега.** Версия пользователя — с `v` или без, нормализуется к
   тегу `vX.Y.Z`; имя zip — `VPNChainSetup-<X.Y.Z>-macos-universal.zip` (тот же шаблон, что
   в release.yml). Правильное имя подтверждается по строке в `SHA256SUMS.txt`.

4. **Проверка суммы — строгая.** `shasum -a 256` по zip; сравнение с суммой из строки для
   его basename в `SHA256SUMS.txt` (`grep -F`). Нет файла, нет строки, суммы не совпали —
   выход с ошибкой до распаковки в целевые места. Все шаги до проверки — только внутри
   `mktemp -d`.

5. **Распаковка и карантин.** Архив создан `ditto -c -k`, распаковка — парным
   `ditto -x -k` (сохраняет метаданные/xattr). `xattr -dr com.apple.quarantine` на `.app`
   во временном каталоге до копирования; отсутствие флага не считается ошибкой
   (`xattr` возвращает ненулевой код, если атрибута нет — обрабатывается как ОК).

6. **sudo только при необходимости.** Сначала проверяется запись в `/Applications`
   (и в существующий `VPNChainSetup.app` при замене) без повышения; если нельзя — те же
   шаги через `sudo`. Замена: существующее приложение удаляется только после успешного
   получения доступа (sudo-пароль уже введён/право подтверждено), затем однопроходно
   `ditto` новой версии — без частичной установки между шагами. Отказ на любом шаге —
   сообщение об ошибке и выход.

7. **Исходник — `scripts/install.sh`, публикация — как есть.** Release.yml добавляет шаг
   копирования скрипта в каталог публикации; в `files:` softprops добавляется `install.sh`.
   Тело релиза переписывается: команда установки одной строкой + ручные шаги как запасной
   вариант (текст про `xattr` сохраняется для ручного пути).

8. **«Одна команда» в README — `curl … | bash`.** Основной способ:
   `curl -fsSL https://github.com/vozhavoronkin/double-vpn-setup/releases/latest/download/install.sh | bash`.
   Аргумент версии при пайпе не передаётся — для конкретной версии README показывает
   скачивание скрипта и запуск `./install.sh vX.Y.Z`. Скрипт определяет, что запущен из
   пайпа, не требуется: поведение одинаковое, аргументы просто отсутствуют.

## Risks / Trade-offs

- [Redirect-трюк зависит от поведения GitHub (302 на `/tag/…`)] → фиксируется тестом на
  живом URL при приёмке; при поломке скрипт падает с понятной ошибкой на шаге
  определения версии, не изменяя систему.
- [Пайп `curl | bash` скрывает код скрипта от пользователя] → README параллельно даёт
  скачивание и ручные шаги; это стандартная практика установщиков CLI.
- [Замена установленного приложения, когда оно запущено] → файлы перезаписываются,
  работающий экземпляр может вести себя странно до перезапуска; README/вывод скрипта
  просят закрыть приложение перед установкой.
- [Частичное состояние при отказе sudo на шаге копирования] → удаление старого
  приложения только после получения доступа; копирование однопроходное; при отказе —
  сообщение об ошибке (старая версия может быть удалена, это допустимо и описано в выводе).
- [bash 3.2 ограничивает синтаксис] → проверка `shellcheck`/`bash -n` в CI не вводится
  (изменение ограничено release-инструментарием); приёмка вручную на чистом Mac по спеке.
- [Старые релизы не содержат `install.sh`] → README отмечает, что скрипт работает с
  релизами, где он опубликован (первый — с этим изменением); для старых — ручные шаги.

## Migration Plan

1. PR с `scripts/install.sh`, правками `release.yml` и README.
2. Эффект проявляется на **следующем** теге релиза (в assets появится скрипт); предыдущие
   релизы не меняются.
3. Откат — revert PR: workflow возвращается к прежним двум assets, скрипт в уже
   опубликованных релизах остаётся, но перестаёт публиковаться заново.

## Open Questions

Нет — решения по версии по умолчанию (последний релиз, аргумент — конкретная версия)
и по «одной команде» (`curl | bash`) зафиксированы выше как допущения; на спеки и
разбивку задач они не влияют.

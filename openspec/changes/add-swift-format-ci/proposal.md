# Proposal

## Why

В проекте нет линтера/форматтера: стиль (4 пробела, `public` в core, русские
doc-комментарии) поддерживается вручную — отсюда расхождения и шумные ревью.
swift-format уже входит в тулчейн Xcode (`xcrun swift-format`), поэтому
автоматизация не добавляет внешних зависимостей (issue #6).

## What Changes

- Добавить `.swift-format` в корень репозитория: ширина строки 100, отступ
  4 пробела, дефолтный набор правил.
- Отдельный job `lint` в `ci.yml`: `xcrun swift-format lint --strict` —
  CI падает при нарушении форматирования.
- Привести существующий код к формату одним отдельным коммитом
  (только форматирование, без изменения поведения).
- Обновить `AGENTS.md`: команда форматирования в «Команды», убрать
  формулировку «Линтера в проекте нет».

## Capabilities

### New Capabilities
- Нет — изменение чисто инструментальное (форматирование, CI-проверка,
  документация) и не меняет поведение, описанное в спеках. В `.openspec.yaml`
  выставлен `skip_specs: true`.

### Modified Capabilities
- Нет.

## Impact

- Новые/изменяемые файлы: `.swift-format`, `.github/workflows/ci.yml`,
  `AGENTS.md`, механический реформат `Sources/` (41 файл), `Tests/`,
  `Package.swift`.
- Поведение приложения и публичные API не меняются; `swift test` остаётся
  зелёным.
- Отклонение от буквального текста issue #6 (согласовано): область проверки
  расширена на `Tests/`, документируемая команда использует префикс `xcrun`
  (локально `swift-format` не на PATH).
- `scripts/make-app-icon.swift` вне области линта.
